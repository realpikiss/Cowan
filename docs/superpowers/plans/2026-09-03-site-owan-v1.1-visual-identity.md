# Site OWAN INTER LINK v1.1 — Distinctive Visual Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "generic template" visual signals on the OWAN INTER LINK site (flat-gradient hero, emoji-as-icons, circular step badges, symmetric card-grid trust badges) with a distinctive, hand-built visual system, and rewrite the site's short marketing copy to be more direct and concrete — without changing page structure or the `js/main.js` DOM contract.

**Architecture:** Same static HTML/CSS/JS site as v1. All changes are: (1) a CSS rewrite of `css/style.css` (hero background treatment, a new inline-SVG icon system, restyled step numerals, a new editorial trust-list layout) and (2) full-content rewrites of all 11 existing HTML pages to consume the new CSS classes, swap emoji for SVG `<use>` icon references, and carry the revised copy. No new pages, no new JS, no new files besides the existing ones.

**Tech Stack:** HTML5, CSS3, hand-authored inline SVG icons (`<symbol>`/`<use>`, no icon font, no external library, no CDN). No JavaScript changes.

## Global Constraints

- HTML/CSS/JS pur — aucun framework, aucun build step, aucune dépendance externe (pas de CDN d'icônes, pas de police externe).
- Le contrat DOM que `js/main.js` consomme est **inchangé** : ids `navToggle`/`navMenu`, classes `whatsapp-form`/`whatsapp-link` avec `data-intro`/`data-message`, structure des `<label for="x">`/`id="x"` dans les formulaires. Aucune tâche de ce plan ne doit renommer ou retirer un de ces éléments.
- Aucune coordonnée réelle n'est connue — tous les placeholders existants (`WHATSAPP_NUMBER` dans `js/main.js`, `[TÉLÉPHONE OWAN]`, `[EMAIL OWAN]`, `[ADRESSE OWAN]`, `[HORAIRES OWAN]`, `OWAN_PLACEHOLDER`, `+225XXXXXXXXX`, `EMAIL_OWAN@example.com`) restent strictement identiques — ce plan ne les touche pas.
- Les icônes SVG sont dessinées à la main pour ce projet (viewBox `0 0 24 24`, pas de `fill`/`stroke` sur les éléments internes — ces propriétés sont héritées via la classe CSS `.icon`), définies comme `<symbol>` dans un sprite `<svg style="display:none" aria-hidden="true">` placé juste après `<body>`, et utilisées via `<svg class="icon" aria-hidden="true"><use href="#icon-xxx"></use></svg>`. Chaque page définit uniquement les symboles dont elle a besoin (liste donnée dans chaque tâche) — pas de sprite universel à 21 icônes sur chaque page.
- Le texte réécrit (services, secteurs, étapes, badges de confiance) est donné mot pour mot dans les tâches ci-dessous — ne pas paraphraser, ne pas inventer de faits au-delà de ce qui est déjà dans `cahier_charge`.
- Pas de suite de tests automatisée (contrainte "zéro build step" inchangée) — vérification par script bash de liens internes cassés + vérifications statiques (grep) décrites dans chaque tâche, comme pour le plan v1.
